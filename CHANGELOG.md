# Changelog

## 1.2b (versionCode 12)

### Дополнительный хук
- Добавлен второй перехватчик: `OplusBrightnessAmbientAdapter.resetAmbientAdapter(String reason)`.
- Блокирует сброс параметров сплайна и интерполяции люксов при вызове с причиной `resetAutoBrightness` или из контекста будильника `AlarmManager`.
- Включена деоптимизация метода для предотвращения инлайнинга в ART.

### Настройки в реальном времени (RemotePreferences)
- Интеграция с `getRemotePreferences("settings")` стандарта LibXposed API 102.
- Во вкладке «Настройки» теперь можно на лету без перезагрузки:
  - Включать/отключать блокировку сброса автояркости (`resetAutoBrightness`).
  - Включать/отключать блокировку адаптера освещения (`resetAmbientAdapter`).
  - Включать строгий режим проверки только по AlarmManager.
  - Включать подробное отладочное логирование (Verbose).

### Автообновления через GitHub
- Встроенный механизм проверки новых версий через GitHub Releases API.
- Прямая загрузка обновлённого APK в один клик.

### Приложение-компаньон (Jetpack Compose M3)
- Полнофункциональный интерфейс с 5 разделами: Обзор, Настройки, Логи, Инструменты, Справка.
- Встроенный просмотрщик логов через root `su logcat` с цветовой индикацией событий.
- Диагностический отчёт для публикации на 4PDA и GitHub.
- Настройка скрытия значка в лаунчере для любителей скрытой работы.

## 1.1 (versionCode 11)

### Идентичность и упаковка
- Пакет: `com.banoku.oplus.autobrightness` (раньше «голый» пакет), автор Banoku (`module.prop`).
- Название «Auto Brightness Guard» + описание на английском и русском (видны в LSPosed).
- Иконка-солнышко (адаптивная, с монохромным слоем для тем Android 13+).
- Нет ни одной активности, значит ярлыка в списке приложений нет.
- minSdk 31, compileSdk 36, targetSdk 36 (Android 16). libxposed API 102.0.0 (`compileOnly`, в APK не попадает).
- Подпись: свой ключ вместо тестового AOSP-ключа `TESTKEY`; схемы v2 и v3.
- Проект теперь Gradle/Android Studio, сборка release без отладочной информации.

### Хук
- Как и раньше, блокируется `OplusAutomaticBrightnessController.resetAutoBrightness()`,
  вызванный будильником сброса после выключения экрана; блокировка постоянная, без таймера.
- Совпадение теперь по двум независимым правилам:
  `lambda` (кадр `lambda$new$1` в стеке) и `alarm` (кадр `AlarmManager$ListenerWrapper`).
  Раньше было только первое, так что переименование лямбды при OTA сделало бы модуль бесполезным.
- Лямбда `lambda$new$1` теперь необязательна: если её нет, хук всё равно ставится (раньше оба
  `getDeclaredMethod` стояли в одном `try`, и отсутствие лямбды отменяло установку целиком).
- Деоптимизация `resetAutoBrightness` и (если найдена) лямбды сохранена, чтобы ART не вкомпилировал
  вызов и хук не обходился.
- Перехватчик «отказывает открытым»: любая внутренняя ошибка приводит к вызову оригинала, а не к
  исключению в `system_server`.
- Остальные вызовы `resetAutoBrightness()` проходят без изменений.

### Логирование (тег `AutoBrightnessGuard`, раньше `AutoBrightnessPatch`)
- Пишется и в журнал модулей LSPosed, и в обычный logcat.
- При старте: версия, SDK, `Build.FINGERPRINT`.
- Итог установки: результат деоптимизации, найдена ли лямбда.
- Каждая блокировка: `BLOCKED reset #N (rule=lambda|alarm)`.
- Первые 10 пропущенных вызовов: `passed reset #N from <цепочка вызывающих>`, чтобы отличать
  «не вызывался» от «вызван, но не совпал».
- Ошибки установки пишутся со стеком.
